# Safety and coverage

- Pin authorized local input paths and hash raw bytes with SHA-256; record filesystem mtime and, if relevant, Git HEAD separately. A HEAD alone does not identify an uncommitted file. Never transmit unpublished content or private locator output, and never compile untrusted TeX with shell escape.
- The optional locator accepts explicit UTF-8 `.tex`, `.md`, `.txt` paths only, validates all before stdout and never writes input. It conservatively masks citations, labels, math, verbatim, comments, quotations, Markdown code and links (including Markdown-like syntax in `.txt`). It exposes common authored TeX prose arguments (`emph`, `textit`, `textbf`, `footnote`, `caption`, `section`, `subsection`, `paragraph`) including starred forms and long titles after optional short titles; short-title arguments are masked and should be reviewed manually. Naked brace groups are not automatically discarded. Unsupported macros, envs, nested/ambiguous syntax, straight quotes used as inches or accents, generated input and Markdown constructs not recognized by the scanner may cause missed prose or false positives. Inspect those spans manually; record actual gaps rather than asserting a coverage percentage.
- Literal quotations and straight-quote ambiguity are protected conservatively. Record unclosed recognized spans as scan failures; the tool does not certify the rest of a failed file. Do not treat stderr skipped counts as coverage. No automated TeX/Markdown scanner can prove all prose seen.
- The locator's questions are neither ban lists nor source-support, scientific, authorship or originality judgments. CLI output is not an audit report.
